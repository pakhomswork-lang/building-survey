# ТЗ: приложение для фиксации обследования зданий (черновик v0.3)

## Цель
Личный рабочий инструмент для бригады (до 7 человек). Фото и данные обследования сразу привязаны к месту на чертеже, структурированы и доступны всем исполнителям. Из этих данных можно быстро собрать материалы для заключения и передать их ИИ с контекстом.

## Принципы
- Работает офлайн: на объекте интернет бывает не всегда (около 70% случаев он есть). Всё сохраняется на устройстве, при появлении сети синхронизируется.
- Фото и данные хранятся раздельно (решение v0.3):
  - **Фото** лежат на телефоне. Пользователь сам переносит их куда удобно (компьютер, сетевая папка, сервер). Автоматической загрузки фото нет.
  - **Данные** (проекты, листы, точки, типы и количество фото, комментарии, участники, настройки) синхронизируются автоматически через сервер. Где работает сервер, решаем перед этапом 2 (см. DECISIONS.md, Р-15).
- Приложение на компьютере работает как «умный просмотрщик»: пользователь указывает папку с фото, приложение находит в ней фото по уникальному имени и показывает их по меткам (лист, точка, помещение, тип).
- Доступ: веб-приложение (PWA), открывается с компьютера, iPhone и Android. Основной браузер на Android — Chrome.
- Участник подключается к проекту по ссылке и сразу получает листы и настройки. Каждая запись помечена автором, чужие данные никто не перезаписывает.
- Все исполнители равны, разных прав нет.
- Минимум обязательных полей, максимум скорости ввода на месте.

## Сущности
- **Проект (объект):** название, участники. На компьютере у каждого пользователя своя указанная папка с фото.
- **Лист:** любой чертёж (план этажа, фасад, разрез, кровля, подвал, фото плана). Загружается из PDF, фото. DWG пока не загружаем, выводим в PDF из AutoCAD.
- **Точка:** положение на листе (в процентах от размера листа), автор, время. К точке привязаны фото, комментарий и, при необходимости, вскрытие.
- **Помещение:** название свободным текстом, необязательно номер по БТИ и оси. Характеристики: произвольные пары «название: значение» (пол, стены, потолок, материал несущих, назначение и т. д.).
- **Фото:** привязано к точке. Тип: общий вид / дефект / замер / узел / вскрытие, шурф. Комментарий к каждому фото не нужен.
- **Комментарий к точке:** необязательный текст.
- **Вскрытие:** точка, тип (пол, стена, потолок, кровля, шурф), слои сверху вниз (материал, толщина, примечание), фото. Для шурфа слои: фундамент и грунты, плюс тип и глубина фундамента.

## Функции по этапам
1. **Ядро (один пользователь):** загрузить лист, поставить точку, снять серию фото, указать тип, посмотреть фото по точке, листу, помещению, типу.
2. **Команда:** сервер и синхронизация, подключение по ссылке, метки всех исполнителей на листе, видно, кто и где снимал (точки, количество фото по типам, автор), и помещения без фото. Превью чужих фото позже.
3. **Помещения и вскрытия:** характеристики помещений (цветовая раскраска на плане), модуль вскрытий с автоматической схемой «пирога».
4. **Выгрузка:** фототаблица в Word с привязкой к месту, ведомость вскрытий, пакет для ИИ (фото с подписью: лист, помещение, тип, комментарий, вскрытие).
5. **Позже:** голосовые комментарии, импорт DWG, версии листов, стрелка направления съёмки.

## Нерешённые вопросы
- Как фото попадают в галерею телефона. Android: тест шага 0 показал, что Chrome сохраняет фото в выбранную папку; осталось проверить, видна ли эта папка в галерее. iPhone: выбора папки нет, проверить «Поделиться → Сохранить в Фото / в Файлы».
- Не теряется ли уникальное имя фото при сохранении в галерею iPhone. Если теряется: записывать номер фото внутрь файла (в EXIF, как дату съёмки).
- Где работает сервер для данных (Р-15) и разрешает ли это IT компании.
- Пример фототаблицы из заключения для настройки выгрузки.

## Риски
- Веб-приложение не умеет надёжно узнавать имя файла из галереи (IMG_xxxx). Поэтому фото снимаются через приложение: оно даёт файлу уникальное имя и записывает его в метки. Выгрузку на диск пользователь делает сам.
- Safari на iPhone может очищать данные неактивных сайтов: нужна кнопка резервной выгрузки фото и меток.
- Конфиденциальность: фото не проходят через сервер приложения. Планы и комментарии хранятся на сервере, поэтому к серверу нужен вход по паролю.
- Если сервер работает на рабочем компьютере: перезагрузки Windows и отключения света. Приложение работает офлайн и досылает данные позже, но нужны резервные копии базы.
