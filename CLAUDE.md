# Проект: приложение для фиксации обследования зданий

Владелец проекта: студент строительного вуза, работает в обследовании зданий и сооружений. Опыт программирования базовый. Объясняй простыми словами, без лишнего жаргона, и коротко.

## Что делаем
Веб-приложение (PWA), работает офлайн. Фото и данные обследования привязаны к точкам на чертежах (листах). Подробности в SPEC.md.

## Как работаем
- Маленькие шаги: одна функция за раз. Сначала короткий план, потом код.
- После каждого рабочего шага, проверенного в браузере, сразу делай коммит и push (без вопроса) и дождись публикации. Только потом пиши итог и «Что проверить на телефоне»: владелец проверяет на телефоне, неопубликованное ему проверить нечем.
- В конце каждого шага отдельным разделом пиши **«Что проверить на телефоне»**: короткий нумерованный список действий и что должно получиться.
- Проверяй кнопки настоящими нажатиями (мышью по экрану), а не вызовом из кода: так видно, что кнопку вообще можно нажать.
- Не меняй то, что уже работает, без причины.
- Если что-то непонятно в предметной области (обследование, вскрытия, помещения), спрашивай.
- Решения записывай в DECISIONS.md.
- Идеи и пожелания «на потом» записывай в IDEAS.md и **не реализуй**, пока владелец сам не попросит взять идею в работу.

## Документы проекта

## Техника
- Стек: Vite + React + TypeScript, PWA (vite-plugin-pwa), база на устройстве — IndexedDB через Dexie (`src/db.ts`), PDF — pdf.js.
- Код в `src/`. Главное: `db.ts` (модель данных и функции записи), `App.tsx` (экраны), `useHashRoute.ts` (переходы через `#/…`), `SheetViewer.tsx` + `usePanZoom.ts` (лист и точки), `PointPanel.tsx` / `CameraView.tsx` (съёмка), `photos.ts` / `photoFolder.ts` (сохранение фото и запись в папку телефона), `PhotoGallery.tsx` / `PhotoView.tsx` / `ProjectPhotos.tsx` (просмотр). Сервер — Supabase (Р-28): `supabase.ts` (подключение), `account.ts` / `AccountForm.tsx` (вход); SQL для базы в папке `supabase/` (`01_…`, `02_…` запускаются по порядку в SQL Editor).
- Команды: `npm run dev` (адрес http://localhost:5173/building-survey/), `npm run build`, `npm run lint`.
- Публикация: push в `main` → GitHub Actions → https://pakhomswork-lang.github.io/building-survey/ (около минуты). Репозиторий https://github.com/pakhomswork-lang/building-survey. `gh` лежит в `C:\Program Files\GitHub CLI`.
- Версия (время сборки) видна внизу главного экрана: по ней владелец проверяет, что телефон получил обновление.
- Новые таблицы в базе — только через новую `db.version(N)`, старые данные должны сохраняться.

## Как проверять
- В браузере в размере телефона (375×812), кнопки — настоящими нажатиями. Тестовые данные удалять после проверки (`db.delete()`).
- Встроенный браузер Claude иногда отдаёт устаревший снимок экрана — перед выводами сверяйся с текстом страницы.
- Камеру и выбор папки на компьютере не проверить: камеру подменять картинкой, папку — внутренней папкой браузера (`navigator.storage.getDirectory()`).

## Словарь
- Лист: любой чертёж (план, фасад, разрез, кровля, подвал).
- Точка: место на листе, к которому привязаны фото.
- Помещение: название, номер по БТИ, оси, характеристики «название: значение».
- Вскрытие: слои конструкции сверху вниз (материал, толщина), включая шурфы.
- Типы фото: общий вид, дефект, замер, узел, вскрытие/шурф.

## Правила данных
- Фото хранятся на телефоне, пользователь сам переносит их в любую папку. Приложение на компьютере находит фото в указанной папке по уникальному имени.
- Данные (проекты, листы, точки, участники, настройки) синхронизируются через сервер. Каждая запись помечена автором, чужие данные не перезаписываются.
- Приложение должно работать без интернета.
- Основной браузер на Android — Chrome.
